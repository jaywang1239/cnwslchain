## 二、问题溯源：为什么会"显示 cnwslChain.com"

用户反馈"网站怎么显示 cnwslChain.com"。经排查，**这不是前端文字显示问题，而是域名归一化缺失**：

- `cnwslchain.com`（裸域）与 `www.cnwslchain.com`（带 www）此前**都能直接打开、都是 200**，没有任何跳转。
- 对搜索引擎而言，这是**两个独立站点**：收录被拆分、外链权重被分散、canonical 指向与实际访问域名可能不一致。
- 用户在浏览器地址栏、在百度搜索结果里看到 "cnwslChain.com"（浏览器会对域名做大小写美化显示），实际因为裸域可访问。

> 事实与推断分离说明：「浏览器地址栏显示 cnwslChain.com」为**实测事实**；「百度搜索结果里出现裸域」为**推断**（未截取百度 SERP 实证），但裸域可访问 + 无跳转是确定的，权重分散风险成立。

## 三、修复措施（已上线）

### 3.1 域名归一化规则

在 `cnwslchain/next.config.mjs` 的 `redirects()` 数组**最前面**插入 host 匹配跳转（Next.js v10.2+ 原生支持 `has: [{ type: "host" }]`）：

```js
// —— 域名归一化：裸域名 → www（301）——
// 避免 cnwslchain.com 与 www.cnwslchain.com 被搜索引擎视为两个站点、分散权重。
// canonical / sitemap / 外链统一使用 www 版本。
{
  source: "/:path*",
  has: [{ type: "host", value: "cnwslchain.com" }],
  destination: "https://www.cnwslchain.com/:path*",
  permanent: true,
},
```

- 置于数组首位，保证在任何其他规则前先生效。
- `/:path*` 通配，**保留原路径**，不会出现"裸域 + 深链接 → 跳到首页"的降级。
- commit：`05da6d119c5149156f2853e528fedd9e860dad3c`

### 3.2 为什么写在 next.config.mjs 而不是 .htaccess

🔴 **关键运维事实**：Hostinger 每次 Git 自动部署时都会**重新生成 `public_html/.htaccess`**，其中只含 Passenger 配置，手工添加的规则必被覆盖。因此所有跳转规则必须写在 `next.config.mjs`，才具备持久性。

### 3.3 308 vs 301 说明

LiteSpeed 服务器对 `permanent: true` 返回 **308** 而非 301。这**不需要修正**：
- 百度官方《搜索引擎优化指南》将 301 与 308 同列为"永久服务器端重定向"，权重传递效果一致。
- 308 相比 301 更严格（要求后续请求方法不变），对 GET 页面访问无任何差异。
