### 2.2 诊断

已确认**正常**的部分：

- ✅ **gzip 压缩开启且生效**（实测 172,834 B → 53,773 B）
- ✅ **HTTP/2 已启用**（ALPN 协商结果 h2）
- ✅ 图片全部 WebP 格式，总计 490 KB，最大单张 79.5 KB
- ✅ 首屏 Hero 图 `fetchPriority="high"` + `preload`
- ✅ 所有 JS 标签带 `async`，无内联样式阻塞
- ✅ 静态资源 `Cache-Control: public, max-age=31536000, immutable`
- ✅ 页面 `s-maxage=3600, stale-while-revalidate=86400`
- ✅ 无 Google Fonts 外链（无国内访问不到的字体阻塞）

**根因：服务器物理位置**

```
www.cnwslchain.com  →  46.202.158.129
IP 归属：Frankfurt am Main, DE（德国法兰克福，Hostinger）
DNS 解析：直连源站，无 CDN
```

- 国内 → 德国单程光纤 RTT 约 250–350 ms。
- HTTPS 需 TCP（1 RTT）+ TLS（1–2 RTT）→ **光握手就 500–800 ms**，这就是 TTFB 的地板。
- **静态资源 TTFB 也是 1.01s**，证明不是动态渲染慢，纯粹是物理距离。

### 2.3 优化建议（按性价比排序）

**A. 接入国内可用的 CDN（收益最大）**

- 在 Hostinger 前挂一层国内可访问的 CDN（如又拍云、七牛、腾讯云 EdgeOne、阿里云 CDN）。
- 国内节点回源德国只在首次；后续命中边缘节点 → TTFB 可降至 **50–150 ms**。
- 注意：国内 CDN 需域名备案。cnwslchain.com 若未备案，可选**香港/新加坡节点**的 CDN（免备案，TTFB 约 200–300 ms）。
- 这一步能把首屏从 3s 级压到 1s 内，是最大杠杆。

**B. 消除 `set-cookie` 对缓存的影响（CDN 落地后必须做）**

- 现状：每个 HTML 响应都带 `set-cookie: cnwsl_locale=zh`。
- 影响：CDN 看到 set-cookie 常会**跳过共享缓存**，导致每次回源。
- 建议：仅在 cookie 值**真的需要变更**时才下发 set-cookie；中文页本身恒为 zh，无需每次重设。

**C. 补充资源提示（低成本）**

- 首页加 `<link rel="preconnect">` 指向 CDN 域名（接入后）。
- CSS 目前是单文件 28 KB / gzip 6.4 KB，**已足够小，无需内联**。

**D. 无需处理**

- 图片已 WebP 且体积健康，不用再压。
- JS 总体 186 KB（gzip）对 Next.js 应用属正常水平。
